# SteamGamers

Текущая архитектура: сайт сохраняет анкеты в закрытую D1-очередь Sites/Cloudflare. Локальный бот забирает их исходящими HTTPS-запросами, подтверждает сохранение и рассылает активным подписчикам. Туннель не нужен. SG_QUEUE_ORIGIN и SG_QUEUE_SECRET находятся только в server/.env; тот же SG_QUEUE_SECRET хранится как секрет хостинга. Браузер использует /api/applications без доступа к очереди.

Для запуска на ПК: server/start.ps1. Компьютер должен работать для рассылки; при выключении сайт продолжает принимать анкеты. После получения ботом облачный payload очищается. Записи старше 7 дней удаляются при следующем опросе. Локальная очистка пока ручная. Уже доставленные Telegram-сообщения не отзываются. Документы на сайте описывают бета-версию; реквизиты оператора и окончательное юридическое оформление остаются незавершёнными.

Сборка: `node build.mjs`; тесты сервера сайта: `node --test worker/test.mjs`; локального бота: `python -m unittest discover -s server -v`. Изменения схемы D1 оформлять новыми SQL-миграциями в drizzle. Старые миграции не менять. Файлы ниже описывают историю демоверсии и не заменяют текущую архитектуру.

Обновление: подготовлен локальный Telegram-сервер с подписками и очередью рассылки. Инструкция: [server/TELEGRAM-SETUP.md](server/TELEGRAM-SETUP.md). Она заменяет прежний сценарий серверного запуска ниже: теперь нужны токен бота, отдельное согласие на рассылку и ключ идемпотентности. Публичная демонстрация пока не подключена к API.

Адаптивная демонстрация лендинга для поиска друзей и напарников в Steam. Интерфейс на русском, без внешних библиотек, шрифтов, аналитики и сетевых запросов из формы.

## Что готово

- Меню и переходы к играм, шагам, преимуществам, анкете и FAQ; мобильное меню.
- Карточки четырёх игр заполняют анкету, есть другая игра.
- Проверка полей и Steam URL, локальный предпросмотр, скачивание анкеты.
- SEO title/description, Open Graph, JSON-LD WebSite, robots.txt и llms.txt.
- Проекты оферты, политики и согласия в модальных окнах. Оператор не выдуман.
- Отдельная презентация: dist/presentation.html и dist/SteamGamers-competitors.pptx.
- Отключённый по умолчанию серверный API с SQLite для будущего российского хостинга, проверкой данных, административным просмотром и удалением по ID.

## Границы демонстрации

Реальные заявки НЕ собираются, автоматического подбора нет. Хостинг Sites не подтверждает российскую локализацию. Оферта, политика и согласие — проекты, не действующие документы. Полное соблюдение законодательства не заявляется. llms.txt и разметка не гарантируют появление в ответах нейросетей или поисковиках.

По условиям задания демонстрация показывает навигацию, интерфейс, SEO/GEO и презентацию. Пункт реального сбора заявок и задание со звёздочкой остаются до запуска. Публичную ссылку считать готовой только после подтверждения публикации.

## Локальный запуск

Из папки dist: `python -m http.server 4173 --bind 127.0.0.1`. Открыть http://127.0.0.1:4173.

## Реальный запуск в РФ

1. Предоставить российский сервер, домен, данные оператора и контакт обращений. Проверить регион основной базы, резервных копий, логов и всех подрядчиков.
2. Утвердить документы с оператором: цель, основания, действия, сроки хранения/удаления, способ отзыва согласия, порядок обращений и условия сервиса. Проверить применимые обязательства с учётом статуса оператора. Заменить проекты на сайте и вынести рабочее согласие в отдельный документ.
3. Разместить dist на веб-сервере с HTTPS; server/app.py запустить от отдельного пользователя за обратным прокси. База хранится ВНЕ dist. Доступ к ней и резервным копиям ограничить; определить ротацию, удаление и восстановление.
4. Настроить SG_ORIGIN (точный https origin), SG_DATA_DIR (закрытый каталог), SG_CONSENT_VERSION (редакция утверждённого согласия), SG_ADMIN_TOKEN (секрет 32+ символа в окружении, не в коде/браузере). SG_ACCEPT_APPLICATIONS=1 включает API. По умолчанию выключен.
5. Проксировать /api/ на 127.0.0.1:8081; ограничить тело 8 KB, частоту отправок, таймауты и доступ к /api/admin/ по VPN или IP администратора. Текущий API не содержит встроенного антиспама и планировщика удаления: их нужно настроить на сервере.
6. После готовности документов изменить обработчик формы в dist/app.js: отправлять JSON POST /api/applications с полями анкеты, consent=true, adult=true и consentVersion. Выводить успех ТОЛЬКО при HTTP 201; при ошибке сохранять введённое и показывать ошибку. Не включать отправку в демонстрационной версии. Обновить кнопку, предупреждения, FAQ, политику, JSON-LD и llms.txt под фактический режим.
7. Проверить сквозной сценарий: тестовая заявка → сохранённая запись → доступ владельца → удаление. GET /api/admin/applications возвращает до 500 последних записей с заголовком Authorization: Bearer <секрет>; DELETE /api/admin/applications/<id> удаляет запись. Просмотр и удаление не предназначены для публичного браузерного интерфейса. Секрет не добавлять в клиентские файлы.
8. Проверить возраст/согласие, отсутствие публичных контактов, адаптивность, резервное восстановление и реальные сроки обработки. Только после этого принимать настоящие анкеты.

## Проверки

`node --check dist/app.js`

Из server: `python -m unittest test_app.py`

Тесты проверяют обязательность возраста/согласия, поддельные домены Steam, размер полей и редакцию согласия. Это не аудит безопасности и не подтверждение готовности рабочего сервиса.
