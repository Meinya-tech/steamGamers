# Рассылка SteamGamers с локального ПК

## Что подготовлено

Один процесс Python обслуживает API формы, получает команды Telegram через long polling и рассылает анкеты из SQLite. Дополнительные Python-пакеты не нужны. Токен не требуется для тестов. По умолчанию приём заявок выключен. Публичный сайт остаётся демонстрацией до подключения.

Получатели — активные подписчики бота на момент принятия заявки. Новым подписчикам старые анкеты не отправляются. Если подписчиков нет, заявка сохраняется без получателей. /start показывает описание; /subscribe включает рассылку; /stop отменяет будущие и ожидающие отправки; /status показывает подписку; /delete_me удаляет chat_id и историю доставки из локальной базы. Группы не подписываются.

В рассылку входят никнейм, игра, публичная ссылка Steam, уровень, цель, время, пояс и комментарий. Обработка требует consent=true, adult=true и отдельного broadcastConsent=true. Все три значения проверяются сервером, версия согласия сохраняется с заявкой. Уже полученные сообщения нельзя отозвать удалением записи на ПК; подписчики могут сохранить или переслать их.

## Когда будет токен

1. Создать отдельного бота у https://t.me/BotFather. Скопировать server/.env.example в server/.env, заполнить SG_TELEGRAM_BOT_TOKEN. Файл .env исключён из Git. Токен не добавлять в dist, переписку или скриншоты.
2. Сгенерировать отдельный случайный административный секрет длиной не менее 32 символов и записать SG_ADMIN_TOKEN. Он нужен для просмотра и удаления заявок, а не для посетителей сайта.
3. После готовности формы, согласий и внешнего адреса установить SG_ACCEPT_APPLICATIONS=1. Запустить server/start.ps1 из PowerShell либо python app.py из server. При занятом порте второй экземпляр не запускается. Проверка подключения не удаляет существующий webhook: для чужого действующего бота требуется отдельная настройка.
4. Оставить ПК включённым, отключить сон на время приёма заявок. Python подключается к Telegram исходящими HTTPS-запросами; для команд бота открывать порты роутера не нужно.
5. Для публичной формы нужен HTTPS-туннель к 127.0.0.1:8081 или домен с обратным прокси. Туннель должен пропускать только POST/OPTIONS /api/applications. Не публиковать /api/admin/, файлы .env и каталог private-data. SG_ORIGIN должен точно совпадать с адресом сайта без завершающего слеша. CORS ограничивает браузеры, но не заменяет защиту от ботов. На туннеле/прокси нужны лимит запросов по IP и лимит тела 8 KB.
6. В рабочей форме заменить локальный предпросмотр на POST на HTTPS-адрес /api/applications. JSON содержит поля анкеты, adult, consent, broadcastConsent, consentVersion (совпадает с SG_CONSENT_VERSION). Отдельный checkbox публикации должен перечислять данные, которые получат все подписчики, и не быть заранее отмечен. Обновить документы с реальными данными владельца, информацию об обработке на ПК и передаче в Telegram.
7. Для каждой новой анкеты создать crypto.randomUUID() в заголовке Idempotency-Key. При повторе того же запроса после сетевой ошибки использовать прежний ключ; для изменённой анкеты — новый. Это предотвращает повторную постановку в очередь. HTTP 201 означает «Заявка сохранена, рассылка в очереди», а не «всем доставлено». Если ПК недоступен, показывать ошибку и сохранять заполненные поля.
8. Подписать два своих тестовых аккаунта, отправить тестовую анкету, проверить доставку обоим, отписку, перезапуск и отказ при отсутствии согласия. Только затем включать реальный сбор на публичном сайте.

## Доставка и ограничения

- Очередь и подписки сохраняются между перезапусками. Отправка идёт примерно по одному сообщению в 1,1 секунды. Платные рассылки не используются.
- 429 откладывает всю очередь на retry_after; сетевые/серверные ошибки повторяются с задержкой, максимум 10 неудачных попыток. После этого запись failed требует внимания владельца. 403 отключает недоступного подписчика. При восстановлении /subscribe включает новые заявки, отменённые старые не возобновляются.
- Доставка не имеет гарантии exactly-once: если Telegram принял сообщение, а соединение оборвалось до ответа, повтор может создать дубликат. Короткий ID анкеты позволяет его распознать.
- При отписке отменяются ожидающие задания; одно уже отправляемое сообщение может успеть прийти.
- Встроенные ограничения: не более одной новой заявки на Steam-профиль в минуту, не более 30 анкет в минуту на весь сервис. Для публичного запуска этого недостаточно без защиты на входном прокси. Автоматической модерации нет: анкеты будут видны всем подписчикам.
- После запуска доступные владельцу статусы — pending/sent/cancelled/failed в таблице outbox. База server/private-data/applications.sqlite3 не должна публиковаться. Для управления существующими заявками используются локальные административные API из README.
- Настроить ограниченные права Windows на каталог данных, резервные копии и регламент очистки; автоматическое удаление по сроку пока не реализовано. Передача в Telegram не подтверждает российское хранение данных.

## Проверка без токена

Из server: `python -m unittest discover -v`. Telegram заменяется тестовым клиентом, сетевых запросов и рассылок нет.

Официальные справки: https://core.telegram.org/bots/api и https://core.telegram.org/bots/faq (проверено 10.11.2026).
